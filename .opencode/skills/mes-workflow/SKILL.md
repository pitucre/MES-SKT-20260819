# 深科特 MES 双库工作流（144 生产 ↔ 179 开发测试）

## 环境与角色（不可混用）

| 环境 | DB | 角色 | 权限 |
|---|---|---|---|
| 172.16.5.144 | `LeanMes` | **生产** | AI **只读**分析；写操作仅限人工发布窗口 |
| 172.16.5.179 | `PROD_TEST_MES` | 开发测试 | AI 可改 SP/表；人工在 Web `http://172.16.5.179/Web/` 测试 |
| 本机 | `localhost:23896` | 开发调试 | IIS Express，物理路径 `Code\Web`，改文件即生效 |

连接串模板（口令同仓库现有脚本，均为 `sa`）：
```
server=172.16.5.144;uid=sa;pwd=SAsa123;database=LeanMes;Connect Timeout=30
server=172.16.5.179;uid=sa;pwd=SAsa123;database=PROD_TEST_MES;Connect Timeout=30
```
连接字符串若需在 PowerShell 中执行 SQL 文件，必须按 UTF-8 读文件后经 `SqlCommand` 执行（避免控制台 GBK 乱码）。

## 阶段① 在 144 读取分析（AI，只读）

- 只允许 SELECT / `OBJECT_DEFINITION` / 系统视图查询；**禁止**在 144 执行任何 INSERT/UPDATE/DELETE/ALTER/CREATE。
- 先在 179 找同名对象对比差异（144 的 SP 常是**旧版**，179 已含多轮修复）。
- 相关手册：`docs/Bug修复测试手册.md`（测试数据速查表 + 各 Bug 操作步骤；生产=144 的说明在其头部）。

## 阶段② 在 179 修改与 AI 自测（AI 主责）

**落盘约定**
- 修改脚本放专题目录（如 `DataSql/bugfix_YYYYMMDD/`），部署副本放 `deploy_179/SQL/`。
- 新建数据库对象一律 `_Program` 结尾（`uspXXX_Program`）；已有对象改名不适用。

**强制备份（AGENTS.md 同源规则，改已有 SP/函数/作业前）**
1. 先导出当前完整定义：
   ```sql
   SELECT OBJECT_DEFINITION(OBJECT_ID(N'dbo.<对象名>'));  -- 类型码不写错；视图/函数同样适用
   ```
2. 存为 `bak_<对象名>_<yyyyMMddHHmmss>.sql`，与修改脚本同目录；179 和 144 都有该对象时**两边都要导**。
3. 备份成功后才允许应用变更；禁止先改后补。

**安全测试（共享测试库铁律）**
- 允许直接测：只读查询、会 RAISERROR 拦截的失败路径。
- **禁止**在共享库直接跑成功路径写操作；如必须，用显式事务包 `ROLLBACK`，或先征得用户同意。
- 测试后自检残留（新 Unit/历史/日志行），有残留立即回滚并汇报。

**应用后验证**
- `sys.sql_modules` 中按本次标记串 LIKE 校验（如 `%包装途中%`）。
- 对新拦截逻辑干跑正/反例，结果用 ASCII 标签输出规避控制台乱码。

**AI 自测完成后**：向用户交付「测试步骤 + 预期结果 + 建议测试数据」（优先用手册速查表中的数据），等待人工测试。

## 阶段③ 179 人工测试（人）

- 用户在 `http://172.16.5.179/Web/`（或 PDA）按步骤验证；AI 待命答疑。
- 用户明确说测试 OK 才进入阶段④；不得跳过。

## 阶段④ 提交 git + TFVC（测试通过后）

- 严格按 `AGENTS.md` 推送规则执行：只 stage 本次任务相关文件；中文提交信息（多主题用 ` + ` 分隔）；GitHub 走 `127.0.0.1:7890` 代理；TFVC 用工作区 `LBJ` 逐文件 tf status/add/checkin，**严禁整目录 checkin**。
- 提交信息中注明“144/179 备份情况”（沿用仓库惯例，如“SP新增xxx并备份144/179”）。

## 阶段⑤ 发布回 144（人工执行，AI 备料）

AI 产出**发布清单**，用户执行：
1. **144 发布前备份**：对将修改的每个 SP/函数，在 144 导出 `bak_<名>_<yyyyMMddHHmmss>.sql`（SSMS 保存结果即可）。
2. **顺序硬约束：先 SP/函数，后页面文件**。页面若引入新 SP 参数而 SP 未更新，整个页面会报错（实例：BatchSNSplit 页 `@Mode` 参数）。
3. **整只覆盖预警**：ALTER 脚本是整只定义覆盖；若 144 从未上过某轮修复，发布会一并带上——清单中必须写明影响面。
4. aspx 等 Web 文件发布到 144 站点对应路径；无编译产物时不需发 DLL。
5. 发布后在 144 冒烟验证（拦截类改动：扫已知反例应被拦）。
